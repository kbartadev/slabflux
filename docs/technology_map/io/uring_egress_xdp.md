# SlabFlux I/O: uring_egress_xdp (`slabflux/io/uring_egress_xdp.hpp`)
# SlabFlux I/O: io_uring Egress XDP (`slabflux/io/uring_egress_xdp.hpp`)

## 1. Architectural Justification
The `uring_egress_xdp` provides high-throughput, non-blocking transmission scheduling for `AF_XDP` sockets. It bridges the gap between the deterministic compute core's asynchronous output and the strict hardware descriptor rings of the NIC, utilizing `io_uring` to orchestrate batched doorbell signaling.
Flushing the AF_XDP transmission ring normally requires a synchronous `sendto()` syscall to ring the kernel's doorbell, which halts the application thread. The `uring_egress_xdp` delegates this doorbell signaling to the `io_uring` subsystem.

## 2. Hardware Implementation Directives
- **UMEM TX Ring Mapping**: Network frames generated by the deterministic engine are allocated within the shared UMEM physical block. The `uring_egress_xdp` maps these raw physical offsets directly into the `AF_XDP` TX ring.
- **Deferred Doorbell Ringing**: Instead of executing a synchronous `sendto()` syscall to ring the NIC doorbell (which invokes an expensive kernel context switch), the egress module aggregates high-frequency micro-writes into massive network bursts, leveraging `io_uring` or batched wakeup calls to signal the kernel to flush the TX ring in bulk.
- **Asynchronous Completion Harvesting**: Reaps completion signals from the `AF_XDP` COMPLETION ring, cleanly recycling the transmitted UMEM frames back into the `spsc_pool` for future outbound events.
- **Asynchronous Doorbells**: The engine prepares the raw Ethernet frames in the UMEM and updates the XDP TX ring. It then submits an `IORING_OP_SEND` via the SQPOLL thread to notify the kernel asynchronously.
- **Batch Amortization**: Aggregates hundreds of outbound `wire_frame` pointers before dispatching a single doorbell signal, heavily amortizing the PCIe and kernel transition overhead.

## 3. Zero-Allocation Pipeline
The egress engine enforces a strictly zero-allocation lifecycle. The pointer emitted by the business logic is the exact physical memory address DMA'd onto the fiber optic wire. Once transmission is verified, the pointer flows cyclically back to the allocation matrix without invoking a single C++ destructor or OS-level `free()` command.
## 3. Pipeline Integration
Functions as a highly optimized transmission scheduler at the tail of the DAG. It consumes state from the `spsc_conduit`, maps it to physical UMEM, and triggers transmission without ever blocking the strategy execution threads.
