# SlabFlux Bridge: Engine Pulse Bridge (`engine_pulse_bridge.hpp`)

## 1. Architectural Overview
Systems often generate non-deterministic external events (e.g., OS signals, hardware interrupts, or random network connections). These cannot be injected directly into the deterministic core without corrupting the timeline.
The `engine_pulse_bridge` serves as the synchronization lock, converting chaotic real-world asynchronous signals into strictly sequenced, deterministic `pulse` events.

## 2. Chronological Stamping
When a non-deterministic thread (like an administrative RPC server) wants to mutate the deterministic matrix:
1. It places its payload into the `mpmc_conduit` attached to the bridge.
2. The bridge, running synchronized to the `branchless_engine`, drains this queue during the designated `AdminBus` polling window.
3. The bridge forcefully stamps the payload with the next available `LSN` generated by the primary temporal clock.

## 3. Execution Integration
By transforming an unscheduled event into a sequential pulse, the bridge guarantees that all nodes in a cluster will see the administrative command (like "Cancel All Orders" or "Update Weights") at the exact same logical point in time relative to the live market data stream.

## 4. Congestion Shielding
If the external system generates thousands of pulses per second, the bridge utilizes `event_arbiter` weighting. It intentionally throttles the assimilation of pulses to prevent them from starving the real-time execution lane, ensuring trading and AI latency remains mathematically flat.
