# SlabFlux Core: Reflection & MOC Fallbacks (`pipeline.hpp`)

## 1. Architectural Overview
The SlabFlux dispatcher relies on static typelists to resolve Event-to-Context mappings and topological relationships at compile-time. This metadata is primarily generated by the external `slabflux_meta` compiler.

## 2. The Safe Context Association Probe
To prevent compilation failures when a type is not registered, the `safe_context_assoc` template implements an ordered SFINAE probe chain.

### Fallback Hierarchy
The system probes for metadata in the following strict order, degrading gracefully:
1. **MOC Output (`reflection::context_association<T>`)**: Checks if the external Meta Compiler generated a rigorous registry map.
2. **Inline Context Maps (`meta::event_context_map<T>`)**: Falls back to inline testing mappings if the MOC was disabled (`SLABFLUX_SKIP_META_COMPILER`).
3. **Empty Typelist**: If no association is found, it silently resolves to an empty `typelist<>`, indicating an Orphan event or an empty Phase Tag.

## 3. Opt-out SFINAE Duck-Typing
If the project is compiled with `SLABFLUX_ENABLE_META_COMPILER=OFF`, the CMake system automatically generates a dummy macro header. The framework cleanly falls back to pure C++20 `requires` concepts and SFINAE duck-typing. While this increases compile times slightly, it allows rapid iteration and debugging without executing the external AST parser.
