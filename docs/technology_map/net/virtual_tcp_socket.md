# SlabFlux Net: Virtual TCP Socket (`virtual_tcp_socket.hpp`)

## 1. Architectural Overview
The `virtual_tcp_socket` acts as the primary API façade for Business Logic and Layer 7 protocol engines (like HTTP and JSON producers). It externally mimics the semantics of standard POSIX sockets (`connect`, `send`, `recv`, `close`), providing complete abstraction over the raw wire, while internally functioning as a 100% user-space, zero-syscall pipeline.

## 2. Invariant-Driven Congestion Mapping
A classic problem in user-space TCP is synchronizing the application's write speed with the network's congestion window (`cwnd`) and the peer's advertised receive window (`rwnd`).

SlabFlux solves this with **Mathematical Aliasing**:
```cpp
uint32_t inflight = tcb_->snd_nxt - tcb_->snd_una;
uint32_t usable_window = (tcb_->snd_wnd > inflight) ? (tcb_->snd_wnd - inflight) : 0;
```
When `virtual_tcp_socket::send()` is invoked, it evaluates the `usable_window`. It then delegates directly to the existing `slabflux::transport::tcp_stream_fragmenter`, passing the `usable_window` as a hard constraint. 

If the window is zero (Zero-Window Backpressure), `send()` immediately returns `0` (the `EWOULDBLOCK` equivalent), physically halting the application layer without sleeping or blocking OS threads.

## 3. Zero-Allocation Outbound Slicing
The `send()` operation takes a contiguous `std::string_view` (e.g., a massive 4MB JSON payload generated by `json_producer`).
1. It calculates how much of the payload fits into the current TCP window.
2. It feeds this bound to the `tcp_stream_fragmenter`.
3. The fragmenter reserves slots on the Wait-Free `tx_unacked_ring`.
4. The data is transferred directly into the 1460-byte MSS payload sectors natively attached to the L2/L3/L4 headers.

There are no intermediate send buffers, no `write()` syscalls, and no dynamic array allocations.

## 4. Application Ingress (`recv`)
While the SlabFlux architecture typically pushes parsed data directly to handlers via the `tcp_stream_defragmenter`, the `virtual_tcp_socket` provides an explicit `recv()` method to maintain full POSIX socket parity for legacy integration.

`recv()` simply performs a wait-free pop from the `rx_stream_ring`. If the ring is empty, it returns `0`, honoring the non-blocking execution invariant of the Sovereign Core.

## 5. Active and Passive Teardown
Invoking `close()` performs an immediate bitmask transition on the TCB to `PHASE_FIN_WAIT1`. The underlying TCP Flow Engine detects this state during its next polling cycle, organically synthesizing and transmitting a `FIN` packet to gracefully collapse the remote connection according to RFC standards.
