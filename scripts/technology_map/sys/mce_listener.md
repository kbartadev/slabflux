# SlabFlux Sys: MCE Listener (`mce_listener.hpp`)

## 1. Architectural Overview
A Machine Check Exception (MCE) is a hardware error generated by the CPU when it detects a physical silicon failure, such as a multi-bit RAM parity corruption or a CPU cache degradation event. The `mce_listener` acts as the absolute fail-safe to prevent structurally corrupted data from traversing the causal mesh.

## 2. Kernel/Hardware Symbiosis
By default, Linux attempts to log MCEs or arbitrarily kill processes. In SlabFlux, uncontrolled process termination leads to split-brain.
The listener integrates with the OS via `/dev/mcelog` or kernel tracepoints:
- It actively listens for Correctable Errors (CE) and Uncorrectable Errors (UCE).
- If an uncorrectable ECC error is detected in a memory bank backing the `mpmc_pool` or `durable_journal`, the hardware is compromised.

## 3. Teleological Agnosia
Upon intercepting a critical MCE:
1. The listener evaluates the silicon fray state.
2. It natively indexes into the Aphasic Horizon.
3. The application structurally forgets how to perceive the corrupted state, allowing it to fall out of the scope of reality without emitting a single quarantine record or halting the CPU.

## 4. Correctable Error Telemetry
For single-bit (correctable) ECC faults, the listener does not halt the pipeline. Instead, it logs the physical DIMM socket address to the `telemetry_node`. If a specific RAM stick exceeds a threshold of correctable errors, the management plane can schedule preventative hardware maintenance.
