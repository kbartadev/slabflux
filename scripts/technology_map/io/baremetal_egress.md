# SlabFlux I/O: Baremetal Egress (`baremetal_egress.hpp`)

## 1. Architectural Overview
The `baremetal_egress` module is responsible for the absolute minimum-latency transmission of network packets. It takes deterministically generated payloads from the SlabFlux compute core and blasts them onto the wire, avoiding all OS-level queuing, TCP segmentation offloads, and kernel interrupts.

## 2. Direct Driver Interface
While standard applications write to sockets and wait for the OS to wake up the NIC driver, `baremetal_egress` interfaces directly with raw memory-mapped transmit (TX) rings.
- **Zero-Copy Transmission**: The payload generated by the execution matrix (which already resides in locked physical memory) is linked directly to a TX descriptor.
- **Doorbell Ringing**: The module manually updates the NIC's physical Tail Pointer Register (the "Doorbell") via Memory Mapped I/O (MMIO). This physically signals the PCIe controller to immediately DMA the frame and push it to the fiber optic transceiver.

## 3. Hardware Shaping & Micro-burst Prevention
In HFT environments, blasting hundreds of UDP packets simultaneously can overwhelm switch buffers (micro-bursting), causing packet drops at the top-of-rack switch.

The `baremetal_egress` integrates with the `hardware_shaper`:
- It explicitly spaces out TX doorbell updates using micro-architectural delays (`_mm_pause` or `TPAUSE` on supported silicon).
- This guarantees line-rate saturation without exceeding the strict inter-packet gap (IPG) tolerances of the receiving exchanges.

## 4. Single-Threaded Monopolization (Sovereign Loop)
The egress module runs on a dedicated, isolated CPU core (the `sovereign_egress` loop). 
- It spin-waits on a wait-free `spsc_ring_conduit` connecting it to the compute core.
- Because it never yields to the OS, the CPU frequency remains permanently locked at maximum boost clocks (C0 state), and the L1 cache remains perfectly hot with the TX ring descriptors.

## 5. Deterministic Retry and NACK Handling
If operating over a reliable multicast or custom UDP protocol, the egress module maintains a `retransmission_buffer`. 
- Instead of allocating new memory for retries, it keeps a sliding window of historical frame pointers. 
- If the `nack_handler` receives a Negative Acknowledgement, the egress loop can instantly re-link the historical pointer to the TX ring, providing O(1) latency recovery for dropped packets.
