# SlabFlux Compute: Physics Reactor (`physics_reactor.hpp`)

## 1. Architectural Overview
The `physics_reactor` is an advanced, SIMD-accelerated processing node engineered to evaluate complex mathematical topologies (e.g., fluid dynamics, options pricing models, or neural mesh weights) in parallel. It is built natively on top of the `vector_lane_engine`.

## 2. Temporal Broadcasting
Traditional physics or pricing loops iterate over arrays and query the system time individually. 
The `physics_reactor` operates strictly on the Reactor Pattern:
- It passively listens for a central `sys::tick_event` generated by the hardware clock steerer.
- Upon receiving the tick, it broadcasts the precise `delta_t` across all active algorithms simultaneously.
- This guarantees that all entities within the simulation share an identical, bit-perfect temporal reality, preventing calculation skew.

## 3. Algorithmic Fusion (`kernels.hpp`)
The reactor leverages metaprogrammed `execution_node` graphs.
Instead of calling `apply_gravity()`, storing memory, and then calling `apply_friction()`, the reactor uses template unrolling to fuse these formulas into a single continuous CPU register operation (`_mm512_fmadd_ps`). 

This eliminates multiple expensive load/store trips to the L1 cache, forcing the entire computational step to resolve inside the AVX-512 ZMM registers before persisting the final state back to the RAM slab.

## 4. Execution Budgeting
The reactor is tightly bound to the `path_budget` and `temporal_guard`. It strictly monitors its own execution cycles via `RDTSC`. If a complex topology calculation threatens to exceed the designated microsecond budget for the tick, the reactor can deterministically shed load or defer lower-priority calculations.
